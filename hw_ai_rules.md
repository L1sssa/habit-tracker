## 3. Функциональность (MVP)

### 3.1. Основные функции

1. **Список привычек** — добавление, удаление, редактирование.
2. **Ежедневные отметки** — отметить привычку выполненной за сегодня.
3. **Streak (серия)** — счётчик дней подряд, когда привычка выполнялась.
4. **Статистика** — процент выполнения за неделю/месяц.
5. **Календарь** — визуальное отображение выполненных дней.

### 3.2. Сущности данных

**Habit (Привычка):**
- `id: string` — уникальный идентификатор
- `name: string` — название привычки
- `description?: string` — описание (опционально)
- `color: string` — цвет для отображения
- `createdAt: string` — дата создания (ISO)
- `completedDates: string[]` — массив дат выполнения (ISO)

**HabitCompletion (Отметка выполнения):**
- `habitId: string` — ID привычки
- `date: string` — дата выполнения (ISO)

### 5.2. Правила архитектуры

1. **Один компонент — один файл.** Имя файла = имя компонента.
2. **Стили — отдельно.** Каждый компонент имеет свой `.css`-файл рядом.
3. **Типы — в `src/types/`.** Общие типы выносятся в отдельные файлы.
4. **Утилиты — в `src/utils/`.** Повторяющаяся логика выносится в утилиты.
5. **Хуки — в `src/hooks/`.** Кастомные хуки начинаются с `use`.
6. **Никакой бизнес-логики в компонентах.** Логика — в хуках или утилитах.
7. **Компоненты не знают о родителях.** Всё взаимодействие — через пропсы.
8. **Не создавать файлы вне структуры проекта.**

## 6. Требования к разработке

### 6.1. TypeScript

- **Запрещён тип `any`.** Использовать `unknown`, union types или generics.
- **Все пропсы типизированы** через `interface` или `type`.
- **Возвращаемые значения функций типизированы** (если не `void`).
- **Строгий режим** (`strict: true` в `tsconfig.json`) — обязателен.
- **Не использовать `// @ts-ignore`** без обоснования.

### 6.2. React

- **Только функциональные компоненты** + React Hooks.
- **Не использовать class-компоненты.**
- **Не использовать `useEffect` без необходимости** — предпочитать `useMemo` и `useCallback`.
- **Не мутировать пропсы** — только читать.
- **Не использовать inline-стили** (кроме динамических значений).

### 6.3. Работа с датами

- **Использовать `date-fns`** для всех операций с датами.
- **Запрещено** использовать `Date.prototype.toLocaleString()` напрямую.
- **Формат хранения дат:** ISO 8601 (`YYYY-MM-DD` или полный ISO).
- **Сравнение дат:** через `isSameDay`, `isToday`, `differenceInDays` из `date-fns`.
- **Часовой пояс:** использовать локальный часовой пояс пользователя.

### 6.4. Хранение данных

- **MVP:** `localStorage` через кастомный хук `useLocalStorage`.
- **В планах:** Supabase (PostgreSQL).
- **Ключ в localStorage:** `habit-tracker:habits` (с префиксом проекта).
- **Формат:** JSON-строка с массивом объектов `Habit`.

### 6.5. Тестирование

- **Vitest + React Testing Library.**
- **Тесты — в файлах `*.test.tsx`** рядом с компонентом.
- **Покрывать:** рендер, клики, граничные случаи.
- **Обязательно тестировать:** расчёт streak, фильтрацию, работу с датами.

### 6.6. Git

- **Conventional Commits:** `feat:`, `fix:`, `refactor:`, `docs:`, `test:`.
- **Один коммит — одно логическое изменение.**
- **Не коммитить:** `node_modules`, `.env`, `dist`.
