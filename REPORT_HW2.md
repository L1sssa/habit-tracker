## 1. Краткое описание проекта и стека (Шаг 1)

**Проект:** habit-tracker — веб-приложение для отслеживания привычек.

**Цель:** помочь пользователю формировать полезные привычки через ежедневные отметки и визуализацию прогресса.

**Стек:**

- React 18 + TypeScript 5
- Vite 8
- date-fns — работа с датами
- CSS — стилизация
- localStorage — хранение данных (MVP)
- Vitest + React Testing Library — тестирование (в планах)

**Структура проекта:**

- src/components/ — компоненты
- src/hooks/ — кастомные хуки
- src/utils/ — утилиты
- src/types/ — TypeScript-типы

**Ключевые требования к коду:**

- Строгая типизация TypeScript (без `any`).
- Функциональные компоненты + React Hooks.
- Один компонент — один файл.
- Работа с датами — только через `date-fns`.
- Стили — в отдельных `.css`-файлах.

**Файл с описанием:** `hw_ai_rules.md`

Context:
- Проект: habit-tracker.

## 4. Chain-of-Thought (Шаг 4)

**Файл:** `prompt_methodology.md`.

**Задача:** Реализовать функцию добавления и отметки привычек.

**Разбивка на 5 шагов:**

| Шаг | Задача | Результат |
|---|---|---|
| 1 | Создать тип Habit | src/types/habit.ts |
| 2 | Создать утилиты для дат | src/utils/dateUtils.ts, streakUtils.ts |
| 3 | Создать хук useHabits | src/hooks/useHabits.ts |
| 4 | Создать компоненты AddHabitForm и HabitCard | src/components/AddHabitForm.tsx, HabitCard.tsx |
| 5 | Создать HabitList и интегрировать в App | src/components/HabitList.tsx, App.tsx |

**Логика цепочки:** каждый следующий шаг использует результат предыдущего.

**Для каждого шага:**

- Промпт по структуре RTCF.
- Результат выполнения (какие файлы созданы).

**Итог:** работающее приложение-трекер привычек.

**Файл:** `prompt_methodology.md`

## 5. Тестирование системы правил (Шаг 5)

**Файл:** `testing.md`.

**Задача:** Сравнить код до и после применения `.clinerules`.

**Вариант «ДО» (без правил):**

- Пропсы не типизированы.
- Стили inline.
- Экспорт через `export default`.
- Использован лишний `import React`.
- Нет отдельного `.css` файла.

**Вариант «ПОСЛЕ» (с правилами):**

- Типизация пропсов через `interface StreakBadgeProps`.
- Отдельный файл `StreakBadge.css`.
- Экспорт через `export const`.
- Форматирование соответствует `.clinerules`.
- Утилита `calculateStreak` вынесена в `src/utils/streakUtils.ts`.
- Проверка на пустой массив.
- Строгая типизация возвращаемого значения.

**Сравнительная таблица:**

| Критерий | ДО | ПОСЛЕ |
|---|---|---|
| Типизация пропсов | Нет | interface StreakBadgeProps |
| CSS-файл | Нет (inline) | StreakBadge.css |
| Экспорт | export default | export const |
| React импорт | Есть (лишний) | Нет |
| Форматирование | Нарушено | 2 пробела, точка с запятой |
| Утилита streak | В том же файле | src/utils/streakUtils.ts |
| Обработка пустого массива | Нет | Есть |
| Количество файлов | 1 | 3 |

**Вывод:** применение `.clinerules` значительно повышает качество генерируемого кода. Cline следует правилам проекта, что снижает необходимость ручной правки.

**Файл:** `testing.md`
